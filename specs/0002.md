## 0. 文档地位与决策摘要

本方案定义下一代站点的产品契约、内容投影、Astro 迁移、SEO、中英双语、上游同步、验证和发布方式。用户于 2026-08-20 批准实施并明确终止日文、韩文支持后：

1. `specs/0001.md` 继续作为上游来源调查、不可变锁、翻译和证据链的历史基线。
2. 本文件取代 `specs/0001.md` 中关于 VitePress、官方同构信息架构、官方菜单、官方路由投影和视觉复刻的目标。
3. 官方简体中文和英文 Markdown 继续保持上游 Git blob 字节不变。
4. 日文和韩文不再属于产品范围；相关内容、状态、路由、翻译 runner、SEO、搜索和验证功能全部删除。
5. 本站不新增教程、解释、实测、FAQ、排错结论或其他原创正文。
6. 本站允许对官方内容做可追溯的 AST 分段、重组、索引、交叉引用、版本差异和结构化展示。
7. 本站允许维护自己的菜单、路由、页面标题、SEO 描述、面包屑、UI 文案和来源标注；这些属于派生元数据，不得引入官方源不存在的事实。
8. 运行时框架迁移到 Astro，VitePress 在迁移完成后从依赖、配置、构建和生成目录中移除。
9. 以 Astro 7.2 和 Starlight 0.39 作为方案编写时的基线；实施时已重新确认并精确锁定 Astro 7.2.4、Starlight 0.41.7。
10. 新结构提高页面与官方整页的区分度，但不承诺 Google 或 Bing 必然收录。搜索引擎结果是发布后验证项，不是代码构建能够证明的事实。

本方案的核心产品定义是：

> 将锁定的 DeepSeek Harness 官方文档转换为一个以主题、实体、API、示例和版本为中心的结构化文档检索站；不改写官方正文，不复制官方信息架构，不以简单换皮或批量同义改写制造差异。

## 1. 背景与问题

### 1.1 当前实现

迁移前生产站点具有以下基线：

- VitePress 静态站。
- 83 个官方 canonical page identity。
- 简体中文根路由、英文 `/en/`、日文 `/ja/`、韩文 `/ko/`。
- 四语言完整发布时为 332 个 HTML 页面，327 个 indexable URL 和 5 个预期 `noindex` 路由。
- `config/upstream-lock.json`、`config/docs-manifest.json`、翻译状态和 `diff-translation` 共同保护上游来源与四语言完整性。
- Vercel Production、Web Analytics、sitemap、IndexNow 和 Bing Webmaster Tools 已接入。

本地迁移完成后的工程基线：

- 只发布简体中文根路由和英文 `/en/`；不存在 `/ja/`、`/ko/` 或翻译状态。
- 85 个 target page identity，生成 169 个中英页面；167 个 indexable、2 个 noindex。
- 717 个中性 source segment 达到 100% coverage 和 one-owner。
- 166 个旧中英 URL 通过永久、单跳 redirect 迁移。

### 1.2 当前索引问题

Google Search Console 已在部分简体中文和英文页面上选择官方 GitHub Pages 站点作为 canonical，而不是本站 self-canonical。已检查样例表明，冲突来自跨域的相同或高度相似主要内容，不是 Astro/VitePress、渲染失败、sitemap 缺失或 canonical 标签语法错误。

Google 的公开规则说明：当多个页面的主要内容相同或非常相似时，会将它们放入一个重复集群；重定向、`rel=canonical` 和 sitemap 只能提供选择信号。Google 仍可选择不同 canonical。Bing 同样会根据内容与搜索意图聚合近似页面。

### 1.3 新约束

本项目明确不采用以下做法：

- 不新增原创正文。
- 不用 AI 批量改写、同义替换或扩写官方文档。
- 不伪造实测、案例、作者经验、版本结论或 FAQ。
- 不向爬虫提供与普通用户不同的内容。
- 不以换框架、换 DOM、换主题或换 title 作为“内容原创”的证明。

因此，本方案只能通过真实的结构化产品价值提高独立收录机会：页面切分、跨源组合、实体索引、代码示例索引、版本差异、内容关系、搜索和新的任务型信息架构。

## 2. 目标与非目标

### 2.1 目标

1. 使用 Astro 完全替换 VitePress，并保持静态生成、Vercel 部署、低客户端 JavaScript 和可抓取 HTML。
2. 保持官方中英文源文件逐字节不变。
3. 将官方整页解析为稳定、可追溯的语义 segment。
4. 使用新的 page projection manifest 将 segment 组合为本站页面。
5. 使用本站自己的菜单、页面边界、路由、title、description 和内部链接。
6. 让每个 indexable URL 对应一个明确的主题、实体、API、示例集合或版本查询用途。
7. 保留官方内容 100% 覆盖，不遗漏标题、段落、列表、表格、代码、Mermaid、图片、链接或受控 HTML。
8. 每个可见官方正文块都能追溯到上游 commit、source page、Git blob、segment ID 和 source hash。
9. 保持简体中文、英文的新页面投影与独立 SEO；英文 fallback 不伪装为中文内容。
10. 继续使用不可变 `diff-translation` 流程更新官方中英文源；该历史技能名不再表示翻译目标语言。
11. 将 Search Console 和 Bing 的 selected canonical/index 状态作为迁移试点的外部 go/no-go 证据。

### 2.2 非目标

1. 不保证 Google 或 Bing 收录全部页面。
2. 不声称本站是 DeepSeek 官方站点。
3. 不删除来源、许可证或上游链接。
4. 不把标题、菜单和布局变化误称为原创内容。
5. 不为达到页面数量而机械拆分每个 H2/H3。
6. 不建立仅用于关键词覆盖的薄页面、标签页或参数页。
7. 不在迁移期间同时发布两套内容相同且都可索引的本站 URL。
8. 不在首次 Astro 改版中引入 SSR、数据库、登录、CMS 或运行时内容生成。

## 3. 成功定义

### 3.1 工程成功

- VitePress 依赖、配置和构建路径全部移除。
- Astro 静态构建、预览、搜索、中英双语、Mermaid、代码高亮、图片、主题和移动导航通过验证。
- 官方中英文锁定 bytes 无变化。
- 日文、韩文内容、状态、runner、schema、测试、路由和发布功能完全移除。
- 100% 官方 segment 被一个且仅一个 primary target page 拥有。
- 生成页面不存在未追溯正文、重复 segment ownership、丢失 block 或非法切分。
- 新旧 URL 迁移表完整，无重定向循环、链式跳转和多个 indexable URL 承载同一本站投影。
- 每个 indexable 页面通过 title、description、canonical、hreflang、robots、Open Graph、Twitter、JSON-LD、sitemap 和内部链接审计。

### 3.2 搜索验证成功

搜索验证按试点 URL 判断，不以提交成功或 HTTP 200 代替：

- Google URL Inspection 显示试点页面允许抓取与索引。
- Google 在重新抓取后对至少一部分试点页面选择本站 self-canonical。
- Bing URL Inspection 不再仅以 `Canonical URL Exists` 或内容质量拒绝全部试点页面。
- sitemap 被 Google/Bing 成功读取，且只包含预期 indexable canonical URL。
- IndexNow 收到更新仅记为通知成功，不记为收录成功。

如果搜索引擎重新抓取后，所有试点页面仍被聚合到官方源，则停止全量内容重组，不以继续扩大页面数量解决问题。

## 4. 内容与来源契约

### 4.1 允许的变化

- 从锁定 Markdown AST 提取完整语义 subtree。
- 调整不同 segment 在目标页面中的排列与组合。
- 将来自不同官方页面的相关 segment 组合到同一目标页面。
- 将一个官方长页拆为多个完整主题页。
- 生成实体、API、类型、事件、配置项、示例、资源和版本差异索引。
- 维护新的菜单、目录、面包屑、上一页/下一页和相关页面关系。
- 维护派生 title、description、导航 label 和结构化数据。
- 来源文件、上游 commit 和许可证只保留在仓库锁、投影收据、审计报告与
  结构化内部数据中；公开文档页面不展示全局来源归属区块。
- 生成不会引入新事实的 UI 标签，例如“来源”“版本”“相关 API”“代码示例”。

### 4.2 禁止的变化

- 修改官方中英文标题、段落、表格、列表、代码、链接文本、图片 alt、Mermaid 或 HTML 的正文 bytes。
- 自动或人工补写解释、总结、建议、结论、案例、排错或 FAQ。
- 将多个句子拼成上游不存在的新句子。
- 截断会改变语义的上下文、条件、否定、警告或安全说明。
- 单独抽取列表项、表格行、代码行或引用的一部分。
- 为 SEO 伪造更新时间、作者、审核者、版本或测试状态。
- 隐藏官方正文以向爬虫展示另一份文本。
- 使用 CSS `content`、canvas、图片文字或点击后注入规避正文审计。

### 4.3 派生元数据例外

以下内容允许由本站维护，但必须能从页面实际 segment 推导，不得添加新事实：

- 页面 route。
- 页面 title 与 H1。
- meta description。
- 菜单 label。
- 面包屑 label。
- 内容类别、实体类型和 relation type。
- JSON-LD 的 URL、语言、日期和许可证字段。

SEO 元数据不是官方正文，必须单独存放，不能写回锁定 Markdown。

## 5. 新信息架构

### 5.1 顶层菜单

目标菜单不再复制官方 Guide、Development、Reference。首次内容盘点按以下七组设计：

| 稳定 ID | 简体中文 | 英文 | 内容用途 |
|---|---|---|---|
| `start` | 开始使用 | Start | 安装、初始化、Web UI、模型与 SDK |
| `concepts` | 核心机制 | Core concepts | Harness、Cordis、生命周期、Effect、服务与事件 |
| `build` | 构建与扩展 | Build & extend | Plugin、Tool、Provider、Package、配置与发布 |
| `runtime` | 运行与编排 | Runtime & orchestration | Session、Workflow、Subagent、计划、任务和运行时子系统 |
| `api` | API 与类型 | API & types | Cordis API、类型、事件、配置项和子系统入口 |
| `examples` | 示例索引 | Examples | 从官方页面提取并按实体/主题索引的代码示例 |
| `versions` | 版本变化 | Version changes | 上游 commit、页面变化、API/标题/示例差异 |

菜单只维护简体中文、英文 label，并由 `navigation.json` 作为来源真值。

### 5.2 路由模型

简体中文继续使用根路由，其他语言保留前缀：

```text
/concepts/cordis/effect-lifecycle
/build/plugins/configuration
/runtime/subagents
/api/cordis/effect
/examples/cordis/effect
/versions/<upstream-commit>/changes

/en/concepts/cordis/effect-lifecycle
```

规则：

- route slug 为语言中立稳定 ID，不因 title 翻译变化而变更。
- route 不包含框架名、年份、营销词或查询参数。
- 同一 page projection 在简体中文、英文拥有同一 neutral route。
- 每个 indexable route 必须 self-canonical。
- locale home 是导航页，可继续 `noindex, follow` 并指向该语言的 Start 首页。
- 搜索、筛选和临时状态使用非索引 URL；不得进入 sitemap。

### 5.3 页面拆分原则

- 按完整主题、实体或用户查询用途拆分，不按固定字数或每个 heading 机械拆分。
- 一个 segment 内部保持源顺序和 AST 所有权。
- 列表、表格、代码块、Mermaid、图片和受控 HTML 不跨 segment 拆分。
- 每个 segment 只允许一个 primary target page；其他页面通过链接引用，不复制正文。
- 一个 target page 可以拥有多个 segment，但必须有明确 page kind：`topic`、`entity`、`api`、`example-index` 或 `version-diff`。
- 纯目录页没有官方正文时默认 `noindex, follow`；只有提供独有结构化检索能力的目录页才可申请 indexable。

## 6. Manifest 与 segment 数据模型

### 6.1 真值分层

迁移后使用以下真值层：

1. `config/upstream-lock.json`：上游 commit、Git tree、blob、SHA-256、bytes 和控制文件锁。
2. `config/docs-manifest.json`：83 个官方 source page identity、官方路径、语言配对和 fallback；不再拥有本站最终 route/menu。
3. `config/source-segments.json`：从锁定 source AST 确定性生成的 segment inventory。
4. `config/content-map.json`：本站 target page、segment ownership、route、page kind 和关系真值。
5. `config/navigation.json`：本站新菜单、分组、顺序和跨页关系。
6. `config/seo-metadata.json`：各 target page 的中英文 title、description、indexability 和结构化数据声明。
7. `config/redirects.json`：旧 route 到新 canonical route 的迁移真值。
8. `config/projection-lock.json`：以上文件 schema/hash、projector 版本、Astro/Starlight 版本和生成结果 fingerprint。
9. `config/projection-state/*.json`：以 target page/segment 为单位记录中英文投影与 SEO provenance。

`website/docs.ts` 在 Astro 运行时不再执行。上游的 `website/docs.ts` 继续作为冻结 discovery 输入，用于检测官方目录变化；本地 publication truth 转移到 JSON manifests。

### 6.2 segment identity

每个 source page 先解析为 mdast，再按不可分割语义 subtree 生成 segment：

```json
{
  "segment_id": "develop.cordis.02#h2-003-effect",
  "source_page_id": "develop.cordis.02",
  "locale": "en-US",
  "heading_path": ["Lifecycle and effects", "Effect"],
  "heading_ordinal": 3,
  "block_start": 18,
  "block_end": 27,
  "source_sha256": "...",
  "ast_sha256": "...",
  "visible_text_sha256": "...",
  "contains": ["heading", "paragraph", "code"],
  "source_blob": "..."
}
```

稳定规则：

- `segment_id` 不仅依赖可翻译 heading 文本，还绑定 source page identity、结构 ordinal 和 subtree hash。
- 中英文 segment 使用相同 source page identity 和结构 ordinal 进行配对，不按可见 heading 文本静默匹配。
- heading 改名、移动、合并、拆分或 subtree hash 变化时，旧 selector 不能静默匹配。
- 一个 selector 匹配 0 个或多个 subtree 都是 blocker。
- 上游 source 发生 material change 后，必须重新审核受影响的 target page composition。

### 6.3 target page schema

```json
{
  "page_id": "concepts.cordis.effect-lifecycle",
  "neutral_route": "/concepts/cordis/effect-lifecycle",
  "kind": "topic",
  "menu_id": "concepts",
  "order": 30,
  "segments": [
    "develop.cordis.02#h2-002-lifecycle",
    "develop.cordis.02#h2-003-effect",
    "reference.cordis.effect#h2-001-effect"
  ],
  "relations": [
    { "type": "api", "target": "api.cordis.effect" },
    { "type": "example", "target": "examples.cordis.effect" }
  ],
  "legacy_routes": [
    "/develop/cordis-tutorial/02-lifecycle-and-effects"
  ],
  "indexing": "index"
}
```

### 6.4 ownership 与覆盖率

`content:audit` 必须证明：

- 每个发布语言的 source segment 覆盖率为 100%。
- 每个 segment 恰好有一个 primary owner。
- 任何重复引用只能是 link/relation，不能复制完整正文。
- target page 输出中的每个正文 text node 都有 source provenance。
- 允许的非 source text 仅限经过 allowlist 的 UI 和派生元数据。
- target page 不得与任何官方整页产生完全相同的有序 segment inventory。
- 不能使用一个“最小相似度百分比”作为通过门槛；报告只做 exact duplicate、ownership、coverage 和人工 page-purpose 审查。

## 7. Astro 目标架构

- Astro 精确锁定为 7.2.4。
- Starlight 精确锁定为 0.41.7，作为文档 shell、可访问性、sidebar、i18n 和组件基线。
- `output: static`，所有 indexable 内容在构建时输出完整 HTML。
- Node.js 保持 `>=22.19.0`，pnpm 继续使用 `package.json` 固定版本。
- 不引入 SSR；交互能力仅使用必要的 Astro island。
- Vercel 继续托管，生产 canonical origin 保持 `https://www.deepseek-harness-docs.com`。
- Vercel Web Analytics 通过 Astro 官方入口只注入一次；不得同时使用 adapter 自动注入和手工组件重复发送。

### 7.4 移除 VitePress

完成 Astro parity gate 后删除：

- `website/.vitepress/`
- VitePress theme 与 config。
- VitePress 专用 `PageData`、head transform 和 sitemap transform。
- `vitepress`、`vitepress-plugin-mermaid` 直接依赖。
- `website/.generated/` 与 `website/.dist/` 生成约定。
- 仅服务 VitePress 的 projector 分支和测试。

保留并迁移：

- Markdown link/image resolver。
- heading anchor 稳定算法。
- Mermaid、代码、图片处理。
- SEO owner、sitemap、robots、IndexNow 和 route audit 的业务规则。
- Vercel Analytics。
- 设计证据和浏览器验证方法。

Vercel `outputDirectory` 从 `website/.dist` 改为 Astro 的 `dist`。`submit-indexnow.ts` 同步只读取新鲜 `dist/sitemap.xml`。

## 8. 页面渲染与独有功能

### 8.1 页面组成

每个 target page 只包含以下区域：

1. 派生 title/H1。
2. 面包屑与菜单。
3. 来源/commit/许可证组件。
4. 一个或多个原样 source segment。
5. 自动生成的实体、API、示例或版本 relation。
6. 上一页、下一页和相关页面链接。

不得生成内容摘要、TL;DR、结论、提示、解释性 callout 或 AI 问答。

### 8.2 API、实体和示例索引

以下能力可由 AST 和锁定源确定性产生，不属于原创正文：

- code fence inventory。
- API/type/event/config identifier inventory。
- identifier → source segment relation。
- example → referenced identifiers relation。
- heading → entity relation。
- source page → target page reverse mapping。
- upstream commit → changed segment mapping。

任何 heuristic 无法唯一判断的 entity relation 必须进入人工 review queue，不能自动发布错误关系。

### 8.3 版本差异

版本页只展示由两个锁定 Git 状态计算的事实：

- 页面增加/删除/移动。
- segment 增加/删除/修改。
- heading、代码、链接、图片和表格差异。
- target page 受影响范围。

没有真实变化的历史版本页不得独立索引；应 canonical 到最新适用版本或不生成。

## 9. SEO 设计

### 9.1 SEO 原则

- SEO 只描述页面真实内容，不用元数据伪造差异。
- title、H1、description 必须在同一语言、同一意图上保持一致。
- title 简洁、唯一、无关键词堆砌和长模板尾巴。
- description 从目标 segment 的主题和可见 source 文本派生，不新增事实。
- indexable 页面 self-canonical。
- hreflang 只链接实际存在、完整且 native 的中英文 target page。
- sitemap 只包含 indexable canonical pages。
- 旧路由、目录页、筛选页、搜索页、fallback 和 redirect document 不进入 sitemap。
- JSON-LD 保留许可证、语言和 canonical URL，但公开页面不得输出
  `isBasedOn`、`citation` 或上游来源路径，也不得声称本站作者撰写了官方正文。

### 9.2 title 模型

每个 page kind 使用可审计模板，但每个 title 由 target page metadata 明确拥有：

```text
topic: <主题>：<所属机制> | DeepSeek Harness
entity: <实体> API、类型与关联项 | DeepSeek Harness
example-index: <主题>代码示例 | DeepSeek Harness
version-diff: DeepSeek Harness <版本/commit> 文档变化
```

模板不能把一个 title 机械复制到所有页面。Google 可能根据可见 H1 和正文重写 title，所以 H1 必须与该 page 的 source segment 主题一致。

### 9.3 exact duplicate 与薄页门禁

`content:audit` 输出 `reports/content-projection-audit.json`，至少包含：

- target page 数。
- source segment 数。
- 100% coverage 证明。
- duplicate ownership 列表。
- exact full-page duplicate 列表。
- orphan/empty page 列表。
- 每页 source page/segment inventory。
- 每页可见 text provenance 分类。
- title/description 重复列表。
- index/noindex/sitemap 决策。
- 人工 page-purpose review 状态。

没有公开可靠的“修改百分比”或“相似度阈值”。本项目不设置用于规避搜索引擎的百分比门槛。

### 9.4 旧 URL 处理

建立显式 `config/redirects.json`：

- 一对一：永久 308 到新 canonical。
- 一对多：旧页面指定一个 primary successor；其他 successor 由新菜单和 relation 链接发现。
- 带 fragment 的旧链接：尽可能建立 heading alias；服务端无法读取 fragment 时，旧页面的 primary successor 必须提供兼容 anchor 或客户端无内容重写的 hash map。
- 不允许 redirect chain、loop、soft 404 或所有旧页面都指向首页。
- 旧 URL 与新 URL 不得同时承载相同且 indexable 的正文。

## 10. 中英双语完整性

### 10.1 上游来源

- 简体中文和英文都直接来自锁定的官方 Git blob，不进行模型翻译或正文改写。
- target page 数从 `content-map.json` 动态推导，不再固定为 83。
- 中英文使用同一 neutral route identity，独立维护 title、description、lang、canonical 和结构化数据。
- 日文、韩文以及其他目标语言不生成内容、状态、路由、搜索索引、hreflang 或 fallback。

### 10.2 fallback

`docs/cordis-api/inherited.md` 是唯一英文 owner。它不与中文 segment 混合成一个自称 `zh-CN` 的 target page；旧中文 URL 永久重定向到英文 owner，sitemap/hreflang 也不广告不存在的中文译文。

## 11. diff-translation 新工作流

### 11.1 保留不变的规则

- 唯一上游仍是 `deepseek-ai/deepseek-harness`。
- `master` 先解析为 full commit。
- run 目录不可变、不可覆盖。
- 官方中英文 bytes 只从锁定 Git blob 复制。
- catalog/control/license/adapter drift 阻断自动 promotion。
- recovery 从原 frozen input 复制，不重新抓取。
- browser evidence 与 formal verification 仍是 material run 完成条件。

### 11.2 新增 projection reconcile 阶段

上游 source promotion 后，新增以下步骤：

1. 重新提取 `source-segments.json`。
2. 将旧 segment selectors 与新 AST 对齐。
3. 输出 `projection-drift.json`：新增、删除、修改、移动、歧义和 orphan segment。
4. 对 selector 0-match、multi-match、source hash 变化和 target page 空洞立即 block。
5. 人工更新 `content-map.json` 后创建 recovery run。
6. 重新运行 segment coverage/ownership/content provenance audit。
7. 重新生成 navigation、SEO、redirects、search 和 target pages。
8. 对所有受影响 target routes 捕获 browser evidence。

禁止行为：

- 自动把新上游段落放入“最近页面”。
- 自动生成连接文字填补语义。
- 因 target page 变化而改写锁定 source。
- 在 projection drift 未解决时更新 upstream lock 并发布。

### 11.3 diff 分类扩展

新增 projection 风险：

- Low：target label/title 元数据变化，segment ownership 不变。
- Mid：同一 source page 内的 segment regroup、route/菜单调整、单个关系变化。
- High：source page 增删、segment 拆并、跨 source composition、fallback、route migration、Astro/Starlight/control/schema 变化。

High 必须人工 review，不能自动 promotion。

## 12. 搜索、分析与 IndexNow

### 12.1 站内搜索

- 使用 Starlight/Pagefind 或等价静态索引，但按 locale 分离。
- 仅索引 canonical target pages。
- 排除 redirect、noindex、fallback、404、搜索页和筛选页。
- 搜索结果返回新 route，不返回 source file 或旧 route。
- API/entity/example/versions 可作为过滤维度；过滤结果页本身 noindex。

### 12.2 Vercel Analytics

- Astro 全局 layout 只注入一次 Vercel Analytics。
- Preview 和 Production 验证脚本路径、page view 和 client navigation。
- 迁移后按新 route 记录页面，保留旧 route → 新 route 对照用于历史分析。
- 不发送 source path、Git blob、用户输入或其他不必要数据。

### 12.3 IndexNow

- key filename 与 UTF-8 内容保持不变。
- `indexnow:check` 改读 `dist/sitemap.xml`。
- 只有匹配 commit 已成功部署，并验证生产 sitemap/key/目标页面后才提交。
- route 迁移时提交新增/更新 canonical URL；旧 URL 的删除/重定向状态按协议和现有脚本能力处理。
- HTTP 200/202 仍只代表接收或待验证，不代表 Bing 索引。

## 13. 测试与验证门禁

### 13.1 source 与 projection

- 官方 Git blob/SHA-256/bytes。
- bilingual pair sidecar。
- source segment AST/visible text hash。
- segment 100% coverage。
- segment one-owner。
- target page 非空、无 orphan。
- 可见正文 text node provenance。
- code/table/list/link/image/Mermaid/HTML 完整性。
- 禁止新增非 allowlist 正文。
- deterministic projection：连续两次构建结果 hash 一致。

### 13.2 Astro 构建

- `pnpm exec tsc --noEmit`。
- Astro content schema。
- Starlight sidebar/locale config。
- 静态 HTML route inventory。
- 404、clean URL、asset cache 和 redirect。
- Mermaid、Shiki、图片、锚点、复制代码和 edit/source link。
- 无 VitePress runtime chunk、class、config 或依赖残留。

### 13.3 SEO

- 每页唯一 localized title/description。
- `html lang`。
- self-canonical。
- reciprocal hreflang 与 `x-default`。
- robots。
- Open Graph、Twitter、JSON-LD。
- sitemap URL/alternate/lastmod。
- robots.txt。
- 目录、筛选和 fallback 不进入 sitemap。
- 旧 URL 响应与 redirect map 一致。

### 13.4 浏览器矩阵

每个 material target route 至少验证：

- 简体中文、英文受影响页面。
- desktop/mobile。
- light/dark。
- 菜单展开/折叠。
- 当前 page 高亮。
- 页面 outline。
- 语言切换保持同一 page identity。
- 搜索。
- Mermaid、代码、表格、图片。
- 页面中不出现全局来源归属区块，同时内部来源锁与版本信息保持可审计。
- 无横向溢出、焦点陷阱和不可访问控件。

## 15. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 仅重组官方内容仍被聚合 | 七页试点后再全量，不承诺收录 |
| 机械拆分形成薄页 | page kind + purpose 人工审查，禁止按 heading 批量发布 |
| 拼接内容被视为低价值 | 只发布具有结构化检索用途的 composition，不生成填充页 |

| 旧 URL 一拆多 | primary successor + relation links + redirect audit |
| 上游 heading 改动导致 selector 错配 | ordinal/hash/AST 多重绑定，0/multi match fail closed |
| 中英 segment 结构漂移 | ordinal/hash/AST 多重绑定，0/multi match fail closed |
| fallback 污染 hreflang | English owner 独立处理，禁止混入中文 native page |
| metadata 引入新事实 | 单独 schema、source-derived 审计和人工 review |
| Analytics 重复上报 | Astro layout/adapter 只允许一种注入方式 |
| IndexNow 被误报为收录 | 报告 receipt 与 indexing 分开 |
