## 1. 目标

在当前空仓库中建立一套独立的 DeepSeek Harness 文档站，满足以下要求：

1. 完整发布官方文档的三个顶层栏目：Guide、Development、Reference。
2. 简体中文和英文使用官方原版内容，不由本项目重新翻译或改写。
3. 日文和韩文以官方英文为唯一翻译源，使用 Codex 翻译。
4. 四种语言共享相同的 page identity、路由、栏目、分组、页面顺序、Markdown 结构和交互壳。
5. 参考 `codex_doc_cn` 的 Astro 文档栈、manifest、locale、搜索、SEO、验证和不可变 evidence 设计，但不复制其中与 ChatGPT/Codex 官网绑定的六菜单、Changelog、组件页、13 locale、`recent-update` 等规则。
6. 在本仓库内实现面向 DeepSeek Harness 官方 GitHub 来源的 `diff-translation` skill，支持后续增量同步、日/韩翻译、验证、恢复和结果报告。

本方案的“原版内容”指正文事实、标题层级、列表、表格、代码、链接、媒体和官方语言措辞与指定上游 Git blob 一致。本站可以使用自己的统一文档壳、搜索、语言选择器和 SEO，但不得改写官方中英文正文。

## 4. 总体技术方案

### 4.1 技术栈

采用 `codex_doc_cn` 已验证的文档栈思路：

- Astro 5 + TypeScript：静态生成和统一 renderer。
- Tailwind CSS 4 + Typography：文档排版与响应式 shell。
- Pagefind：按 locale 生成隔离的静态搜索索引。
- Shiki：代码高亮。
- Mermaid：构建期或受控客户端渲染 `mermaid` fence。
- Playwright：全量 route/DOM/可访问性/移动端自动验证。
- Computer Use 或连接的 Chrome：正式可见页面证据和与官方中英文页面的抽查对比。
- Node.js 脚本 + Python snapshot manager：source capture、不可变 run、promote、verify 和 result。

不直接复制 `codex_doc_cn` 的页面内容、Codex 专属组件或 13 locale UI 数据。只复用可泛化的 shell、manifest、route、SEO、search、hash evidence 和 fail-closed 方法。

### 4.2 路由模型

简体中文保持默认根路由，其他语言使用 locale 前缀：

| locale | route prefix | 示例 |
| --- | --- | --- |
| `zh-CN` | 空 | `/guide/quickstart` |
| `en` | `/en` | `/en/guide/quickstart` |
| `ja` | `/ja` | `/ja/guide/quickstart` |
| `ko` | `/ko` | `/ko/guide/quickstart` |

三个顶层栏目统一为：

- `/guide/...`
- `/develop/...`
- `/reference/...`

部署在子路径时只由 Astro `base`/运行环境处理，不把 GitHub Pages 仓库名前缀写入 manifest 或 Markdown。

### 4.3 页面和语言事实源

`config/docs-manifest.json` 是本站 page identity、上游源路径、本地路径、route、导航 placement、source kind、render feature 和 SEO 状态的唯一事实源。

`config/docs-locales.json` 是 locale、前缀、内容根目录、源语言和发布状态的唯一事实源。

`config/upstream-lock.json` 记录最近一次已验证同步的上游仓库、branch、commit、tree、`website/docs.ts` hash、VitePress 配置 hash 和 publication fingerprint。

页面数和 route 数一律从 manifest 与 locale 配置动态计算。83、3、17、62 和 332 只作为首次导入验收快照，不作为永久常量。

### 5.1 保证中英文原版的方法

中英文发布文件不增加本项目前置 frontmatter，不把 review 状态写进正文。页面元数据全部放在 manifest 和 sidecar 中。

每个官方文件从固定 commit 读取原始 bytes，复制到与本站 route 对应的本地路径。文件名可以变化，但内容 bytes 不变，因此：

```bash
git hash-object <local-file>
```

必须等于 GitHub tree 中记录的上游 blob SHA。中文 `.zh.md` 可以在本地保存为普通 `.md` 路径，但 bytes 仍须等于上游 `.zh.md` blob。

官方 Markdown 在 H1 后包含 GitHub 用的中英文切换行。本站文件继续保留该行以维持 blob 完全一致，但 renderer 在输出 HTML 时识别并隐藏这条 repository chrome，改由全站四语语言选择器呈现。日文和韩文的翻译输入使用去除该切换行后的规范化英文 body。

相对链接不能按本地复制后的文件位置直接解析。resolver 必须以 manifest 中的 `upstream.source_path` 为基准：

- 目标已在本站 manifest：改写为当前 locale 的本站 route。
- 目标存在于上游但未公开：链接到固定 commit 的 GitHub blob/tree。
- 图片：从固定 commit 导入到本站资源目录并记录 SHA-256。
- 缺失目标或逃逸仓库根目录：阻断构建。

## 6. Manifest 设计

建议页面记录：

```json
{
  "page_id": "dsh.guide.quickstart",
  "upstream": {
    "repository": "deepseek-ai/deepseek-harness",
    "english_path": "docs/user/guide/index.md",
    "chinese_path": "docs/user/guide/index.zh.md",
    "pair_record_path": "docs/user/guide/index.i18n.yaml",
    "source_kind": "authored_pair"
  },
  "local": {
    "canonical_route": "/guide/quickstart",
    "english_path": "docs-en/guide/quickstart.md",
    "chinese_path": "docs/guide/quickstart.md"
  },
  "navigation": {
    "tab": "guide",
    "section_id": "guide",
    "order": 1,
    "labels": {
      "zh-CN": "使用 Web UI",
      "en": "Use the Web UI",
      "ja": "Web UI を使用する",
      "ko": "Web UI 사용"
    }
  },
  "render_kind": "markdown",
  "features": [],
  "indexable": true
}
```

`source_kind` 至少支持：

- `authored_pair`：官方中英文成对文件。
- `generated_pair`：英文由上游生成器维护、中文为官方审核 counterpart；本站仍按 blob 导入，不执行上游 generator。
- `upstream_english_fallback`：官方中文 route 故意复用英文，当前只用于 `cordis-api/inherited.md`。

`features` 至少支持 `mermaid`、`images`、`controlled_html` 和 `deep_outline`。所有页面仍走统一 Markdown renderer，不为单页复制页面壳。

## 7. 上游导入与安全边界

### 7.1 获取方式

同步工具使用 GitHub API 或临时只读 shallow fetch 获取：

- `refs/heads/master` 的确切 commit。
- 该 commit 的 tree。
- `website/docs.ts`、`website/.vitepress/config.ts`、`scripts/project-doc-site.ts` 和 Pages workflow。
- manifest 中声明的英文、中文、`.i18n.yaml` 和图片 blob。

所有请求都记录 URL、commit、blob SHA、bytes、时间、状态和本地 SHA-256。不得使用浮动 raw URL 的返回内容直接 promote；必须先解析并冻结 commit。

### 7.2 不执行上游代码

同步过程不得 import 或执行上游 `website/docs.ts`、VitePress 配置、generator、MDX、HTML script 或 package script。

首次 manifest 从已人工核验的 `website/docs.ts` 建立。后续每轮记录该文件 hash：

- hash 未变：可以按已审核映射同步正文。
- hash 变化：先阻断为 catalog drift；人工对照新文件和线上三栏，更新 manifest 后创建 recovery run。

这样可以使用 GitHub 真源，同时避免把上游 TypeScript 当成本地可信代码执行。

### 7.3 官方双语配对校验

上游已有 `foo.md`、`foo.zh.md`、`foo.i18n.yaml` 配对约定。导入器要读取 sidecar 中的两个 Git blob SHA，并验证它们分别等于当前固定 commit 中的英文和中文 blob。

以下情况全部阻断：

- paired 页面缺少任一文件或 sidecar。
- sidecar blob SHA 与固定 commit 内容不一致。
- 中文/英文文件结构签名不一致。
- 官方 manifest 声明 paired，但本地误用了 fallback。
- fallback 页面突然获得中文 counterpart，却没有进行 catalog/source kind 审核。

### 7.4 许可证与归属

上游仓库当前声明 MIT License。实施时必须重新核验固定 commit 中的许可证文件，在本站保留 DeepSeek Harness 来源链接、固定 source commit 和适用的许可证/归属说明。不得移除上游文件自带的版权或许可证声明；若上游许可证发生变化，source trigger 必须阻断并要求人工复核，不能按旧结论继续导入。

## 8. 文档渲染与站点能力

### 8.1 统一文档壳

四种语言共用：

- 顶部品牌、Guide、Development、Reference 导航。
- 桌面侧栏和移动抽屉。
- 当前栏目、分组和页面高亮。
- 右侧页内目录。
- 上一篇/下一篇。
- 代码复制按钮。
- 主题切换。
- 四语同页切换。
- “查看官方源文件”链接，指向本轮固定 commit，而不是浮动 `master`。

locale 分支只选择文案、route 和内容文件，不能选择另一套结构或 renderer。

### 8.2 Markdown 与安全 HTML

支持 GFM、表格、任务列表、代码 fence、显式 anchor、`details/summary` 和 Mermaid。

上游可见 HTML 只按 allowlist 作为 inert markup 解析。阻断：

- `script`、`iframe`、`object`、`embed`。
- 任意 `on*` event handler。
- `javascript:` URL。
- 未知自定义组件或需要执行表达式的标签。

当前官方发布页中存在大量生成 anchor/受控 HTML、3 个 Mermaid 页面、9 个含图片的英文页面，没有直接视频。实现时仍从 manifest 动态审计，不能把这些数量写成长期豁免。

### 8.3 搜索与 SEO

- 每种 locale 生成独立 Pagefind index，切换语言时只加载对应索引。
- 四语页面使用 self-canonical。
- 每页输出 `zh-CN`、`en`、`ja`、`ko` 互返 `hreflang` 和 `x-default`。
- sitemap 动态覆盖全部已发布 page × locale。
- 标题和 description 优先使用当前语言正文 H1/首段；后续可以增加人工审核的 SEO layer，但不得改正文。
- 搜索结果、面包屑、侧栏和页内目录使用当前 locale。

## 9. 日文与韩文 Codex 翻译

### 9.1 来源和范围

- 日文、韩文的唯一源是 promote 后的最终 `docs-en`。
- 不得从官方中文、日文旧译、韩文旧译或另一译文转译。
- 首次 bootstrap 使用显式 `--all-pages`，当前为 83 页。
- 日常同步只允许显式 `--page-id` 或 `--page-ids`，集合严格等于 material changed/new 页面。
- 完整 locale 审计覆盖所有页面，但不能因此重译未变化页面。

### 9.2 持久化翻译状态

为了不污染官方中英文原版文件，翻译状态写入 `config/translation-state/<locale>.json`，每页至少记录：

- `page_id`
- `source_path`
- `source_git_blob_sha`
- `source_sha256`
- `normalized_source_sha256`
- `target_path`
- `target_sha256`
- `translation_review`
- `model`
- `model_fingerprint`
- `reasoning_effort`
- `reviewed_at`

模型、推理强度和 cache key 必须显式记录，避免后续对比把模型变化或旧缓存误判为内容效果。

### 9.3 增量翻译

changed 页面使用 promote 前备份的旧英文、旧译文和新英文做结构块对齐：

1. 只有旧译文为 `approved` 且其 `source_sha256` 精确匹配旧英文时，才允许复用未变化块。
2. 标题、段落、列表项、表格行、callout、代码 fence 分块对齐。
3. 翻译变化块时提供相邻英文块作为只读上下文。
4. 结构错位、重复块歧义、源 hash 不符、SEO/title 变化、Codex 输出无效或整页审计失败时，自动回退全页翻译。
5. 单页全部检查通过后才原子写入目标文件；禁止留下半页译文。

### 9.4 结构保护

日文和韩文必须保留规范化英文源的：

- heading level 和顺序。
- fenced code 的 fence、info string、空白和内容。
- inline code token。
- link/image destination。
- list kind、编号和 item 数量。
- table 行列、顺序和 cell 结构。
- HTML tag 结构与属性中的技术字面量。
- Mermaid 源码；图中自然语言只有在安全、可验证的受控路径下翻译，否则保留原文。

### 9.5 语言规则

新建 `.agents/skills/diff-translation/references/locale-style-guide.md`，只维护 DeepSeek Harness 的共同规则、日文和韩文规则。

共同保护词至少包括：`DeepSeek`、`DeepSeek Harness`、`dsh`、`Cordis`、`Typert`、命令、flag、包名、路径、配置键、类型、事件、API、协议值和版本号。

日文：

- 使用自然、克制的现代开发者文档语气和统一的「です・ます」体；标题可用简洁体。
- UI 文案、目录、搜索、复制按钮和无障碍名称全部本地化。
- 禁止残留成段中文或韩文；汉字本身不能被简单当作中文污染，需要按日文词法审计。

韩文：

- 使用自然的正式说明体和标准韩语分词。

### 10.3 稳定工作流

#### 阶段 0：触发门禁

1. 读取 `origin/main` 中的 `config/upstream-lock.json`。
2. 查询上游 `master` HEAD 和 tree。
3. 计算 publication fingerprint：
   - `website/docs.ts`
   - `website/.vitepress/config.ts`
   - `scripts/project-doc-site.ts`
   - Pages workflow
   - manifest 当前映射的所有 Markdown、pair sidecar 和资源 blob
4. fingerprint 相同：成功 no-op，不创建空 run、commit 或 PR。
5. 只有非文档代码 commit 变化但 publication fingerprint 相同：仍为 no-op。
6. 网络、权限、ref、tree 或 hash 不明确：阻断，不能猜测。

#### 阶段 1：Prepare

创建唯一 `.docs-source/runs/<run-id>/`，冻结：

- 上一版 lock、manifest 和 locale 配置。
- 上一版中英文内容 hash。
- 日/韩 translation state。
- run 创建时间和基线 lineage。

目录已经存在时拒绝复用。

#### 阶段 2：Capture 与 Discover

- 从 GitHub 固定 commit 保存 publication control files、tree 和当前全部映射 blob metadata。
- 用浏览器捕获线上三栏当前可见 route、label、section 和顺序，并记录页面 edit-source URL。
- 比较 manifest，报告 canonical 增删、source path 变化、route 变化、换组、改名、重排和 fallback 状态变化。
- `website/docs.ts` hash 或线上 placement 有任何未审核变化时，当前 run 阻断；修复 manifest 后创建 recovery run。

#### 阶段 3：Fetch 与 Pair Validation

- 每个 manifest 页面恰好抓取一次固定 commit blob。
- authored/generated pair 验证 `.i18n.yaml` 中的两个 Git blob SHA。
- fallback 页面验证显式例外。
- 图片按 manifest/source link resolver 抓取并绑定 bytes/hash。
- 任一文件缺失、SHA 不符或 path 越界时阻断。

#### 阶段 4：Normalize 与 Diff

- raw bytes 永久保留，不执行内容。
- 规范化副本只用于语义比较和翻译：去除 repository language switcher、统一无语义空白，解析受控 Markdown/HTML。
- 语义 diff 保留 H1、heading、正文、代码、link target、图片 label、列表、表格和 Mermaid。
- 分别记录 `catalog_change`、`english_change`、`chinese_change`、`pair_change`、`asset_change`、`render_change`。

#### 阶段 5：Report 与人工分诊

- `new`：完整中英文 blob + 日韩全页翻译。
- `changed`：中英文官方 blob 同步 + 日韩增量翻译。
- `moved`：route/redirect/导航处理，内容 hash 不变时不重译。
- `removed`：人工判断 redirect、retired 或仍为 linked-only，禁止直接删除。
- `pair_invalid`、unknown HTML、manifest drift、fallback drift：blocker。

#### 阶段 6：事务式 Promote

中英文作为同一个事务 promote：

1. dry-run 校验目标 path、blob SHA、manifest 和完整 staging tree。
2. 备份旧 `docs-en`、`docs` 和资源清单到 run。
3. 在临时目录写完整新树。
4. 重新计算所有 blob/hash。
5. 原子替换。
6. 保留 rollback 路径。

禁止只 promote 英文或只 promote 中文。

#### 阶段 7：日文和韩文翻译

- 冻结 material `translate_page_ids`、最终英文 hash、manifest 和 locale 配置。
- `ja`、`ko` 各自执行 dry-run、翻译、完整 locale 审计、全页语境复核和 hash-bound review receipt。
- 两种语言写入范围相互隔离。可以由 translator 进程有限并行，但每个 locale 内部保持串行步骤，且不在 worker 中运行全站 build。
- 冻结输入漂移时整批作废并进入 recovery，不能混合不同 source generation。

#### 阶段 8：最终验证与浏览器证据

- 可重复 `preflight-final` 通过后，运行一次正式 final pipeline 和一次生产 build。
- 全量自动 DOM 校验覆盖全部 page × locale。
- 中英文与官方线上对应页进行结构和可见内容比较。
- 日文和韩文与规范化英文进行结构指纹比较，并执行语言污染检查。
- Computer Use/Chrome 对所有高风险页、Mermaid 页、图片页、controlled HTML 页和各栏目代表页形成正式可见证据；普通 Markdown 页由全量 DOM 检查覆盖，changed/new 页面按风险扩大截图范围。

#### 阶段 9：Evidence、Verify 与 Result

working evidence 全部生成后先执行只读 dry-run。通过后按固定顺序只导入一次：

1. `upstream`
2. `catalog`
3. `translation`
4. `assets`
5. `seo`
6. `browser`
7. `build`

正式 `verify` 只运行一次。失败后不得在同一 run 替换 evidence，必须创建 recovery run。

`result --all-actionable` 只有在 formal verification passed 后成功，并原子更新 `diff/`。

#### 阶段 10：可选发布

默认 skill 不提交、不推送、不建 PR。只有用户明确要求发布时：

- 检查 branch、remote、worktree、staged scope 和 secrets。
- 从 `origin/main` 创建 `codex/diff-translation-<date>-<id>`，或在已授权的当前 feature branch 工作。
- commit、push 后创建目标为 `main` 的 PR。
- 验证远程 SHA 和 PR base/head/state；不自动 merge。

## 11. 不可变 run 与恢复

建议 run 结构：

```text

├── run.json
├── metadata/
│   ├── upstream.json
│   ├── publication-fingerprint.json
│   ├── live-navigation.json
│   └── final-input-state.json
├── raw/github/
├── normalized/
├── backup/
│   ├── docs-en/
│   └── docs/
├── reports/
├── reviews/
├── working-evidence/
├── evidence/
├── ledger/
└── screenshots/
```

规则：

- run 内容只追加，不覆盖。
- 抓取中断或 catalog 修复后使用 `prepare --recovery-run-id <source-run-id>`。
- recovery 复用原 run 的固定 commit、tree、raw blob 和旧中英文 backup；缺失或 hash 不匹配时 fail closed，不能悄悄改抓网络 HEAD。
- recovery 重新捕获当前线上导航，并重新生成所有带时间约束的 aggregate i18n、build 和 browser evidence。
- 只有成功 `result --all-actionable` 后才能按日期清理更早 run；保留成功日期的所有 cross-run lineage。
- `diff/` 不是历史库，只保留最新结果投影。

## 12. Diff 分诊与风险等级

每页独立记录：

- `route_change`
- `navigation_change`
- `english_change`
- `chinese_change`
- `pair_integrity_change`
- `translation_change`
- `asset_change`
- `render_change`
- `seo_change`

风险等级只用于审核优先级，不用于过滤页面：

- `high`：新增/删除/合并/拆分页面，`website/docs.ts` 结构变化，官方 pair 失效，权限/安全/协议核心内容大改，generated reference 大范围变化，unknown HTML。
- `mid`：多节正文、表格、Mermaid、图片、受控 HTML 或大量 API 字面量变化。
- `low`：单段澄清、链接、标签或小范围文字变化。

所有 low/mid/high material 页面都必须进入日韩翻译集合、evidence 和最终结果。

## 16. 主要风险与对策

| 风险 | 对策 |
| --- | --- |
| 上游 `master` 持续变化 | 每轮先解析 commit，所有内容绑定固定 SHA；浮动 HEAD 不进入 promote |
| `website/docs.ts` 是 TypeScript 且含程序表达式 | 不执行上游文件；hash 变化即阻断并人工 reconcile manifest |
| 中文和英文在上游同等权威，不一定永远由英文驱动 | 中英文作为配对事务导入；只把日/韩翻译源固定为英文 |
| 上游 pair sidecar 陈旧 | 校验 Git blob SHA；不一致时阻断并等待上游或人工确认 |
| 本地 route 与上游文件路径不同导致相对链接错误 | 所有链接按 manifest 的 upstream source path 解析 |
| Reference 很长且包含 generated content/HTML | raw 保留、HTML deny-by-default、结构审计、长页性能预算 |
| 日文汉字被误报为中文污染 | 日文使用词法/假名比例与禁用短语组合检查，不用简单 Han 字符阻断 |
| Codex 输出结构损坏或术语漂移 | protected syntax、重试、整页校验、full-page fallback、人工 review receipt |
| GitHub API 限流或网络中断 | 支持固定 commit shallow fetch；未完成 run 保留并走 recovery，不切换到网页抓正文 |
| GitHub Pages 与 `master` 暂时不一致 | Git blob 是正文真源，线上只做 deployment/render 校验；证据分别记录 source commit 与页面 checked_at |
| 首次 332 页浏览器成本较高 | 全量自动 DOM，风险分层正式截图；高风险、资源、Mermaid、栏目代表页重点人工核对 |
